## 前提：このリモート環境では「Gitリポジトリだけが永続化される」

まず重要な制約を押さえます。あなたが今使っている Claude Code on the web の実行環境は**エフェメラル（使い捨て）**です。セッションごとにコンテナが新規に立ち上がり、リポジトリを clone し直し、終了後は破棄されます。

つまり「私が**いつでも**参照できるデータベース」を作るには、**Gitリポジトリにコミットされたファイル**として持つのが唯一かつ最も確実な方法です。外部DB（SQLite/Postgres等）に置いても、ネットワークポリシー・認証情報・接続の永続性の問題があり、毎回つなぎ直す手間とリスクが増えるだけでメリットがありません。

結論：**`docs/sessions/` のようなディレクトリに、Markdown + 索引ファイルでセッション履歴を蓄積し、SessionStart フックと `CLAUDE.md` で「毎回自動で読み込ませる」**のが最も効果的です。

### なぜこの形か

| 要素 | 役割 | 効果 |
|------|------|------|
| **セッションごとの `.md`** | 何を・なぜ・どう決めたかの詳細 | 後から私が文脈を完全に復元できる |
| **`log.jsonl`（索引）** | 1行1セッションの要約（日付/タグ/要点/ファイルへのパス） | `grep` で瞬時に該当セッションを発見。全文を読まずに当たりをつけられる |

| **SessionStart フック** | 起動時に索引と直近Nセッションを自動表示 | 私が「履歴の存在に気づかない」事故を防ぐ |
| **`CLAUDE.md`** | 参照を恒久ルール化 | フックが無い環境でも私が必ず確認する |

- フックが受け取る `transcript_path` を `jq` で解析し、以下を**自動抽出**:

- **session_id をキーに upsert**（追記ではなく上書き）。

- **デバウンス**: トランスクリプトの更新が無ければ再処理しない（速度対策）

### 動作（3つのフックで全自動）
| タイミング | 処理 | コスト |
|---|---|---|
| **Stop**（応答ごと） | トランスクリプトを `jq` で解析→全文`.md`＋索引`.jsonl`をローカルに upsert | **追加LLMトークン0**・デバウンスで未更新時はスキップ |
| **SessionEnd**（終了時1回） | 一時worktreeで専用ブランチ`session-history`へ集約コミット＆push | 毎ターンpushしない＝ネットワーク/速度に配慮 |
| **SessionStart**（起動時） | 索引から直近5件の要約だけ提示 | **約600トークン固定**（履歴件数に依らない） |

### 実測で確認した効率
- **全文記録でも生ログの約7%**（ツール出力ノイズを除外）。1件8〜30KB、索引は300B/件 → 1000件でも索引300KB・全文30MB程度。
- 全文は私が**必要な1件だけ grep→参照**（約2,400トークン/件）。何千件あっても起動コストは増えません。
- 検証済み：抽出の正確性／デバウンス／orphanブランチ作成／**session_idでのupsert（重複しない・更新反映）**／起動時の要約表示。隔離リモートでテストし本番origin汚染なし。

### 有効化について
このシステムは**次回セッションから自動稼働**します（フックは起動時に読み込まれるため、現セッションには未適用）。データ用の`session-history`ブランチは、次にこのリポジトリでセッションが終了した時点で自動作成されます。
